# utm-gsheets

Нативный Cordis-плагин для DeepSeek Harness: набор тулов для работы с
**Google Sheets** через официальный API v4 (`gsheets_*`): чтение/запись,
форматирование, формулы, управление листами, пакетные операции и diff.

Ключевая идея: **переиспользует существующий OAuth-токен** пользователя
(путь к нему задаётся при установке — через `config.token_path` или
`GSHEETS_TOKEN_PATH`) с авто-обновлением access-токена через refresh token.
**Service account и настройка Google Cloud не нужны** — всё работает на уже
выданном installed-app токене (scopes `spreadsheets` + `drive` уже есть).

## Структура

```
plugin/
├── index.js            # вход плагина Cordis (регистрация тулов через defineTool)
├── src/
│   ├── config.js       # конфиг: где лежит токен (путь, без секретов в репо)
│   ├── client.js       # OAuth2 (refresh) + Sheets v4 API обёртка
│   └── tools.js        # хендлеры + JSON-схемы тулов
└── test/
    └── run-tests.mjs   # автономные тесты (node test/run-tests.mjs)
```

## Возможности

| Тул | Что делает |
| --- | --- |
| `gsheets_meta` | Метаданные таблицы + список листов (tabs) с числом строк/колонок |
| `gsheets_list` | Прочитать лист: строки как объекты (заголовок = ключи) или сырые массивы; опциональный A1-диапазон |
| `gsheets_get` | Прочитать точный A1-диапазон как сырые строки (formatted / formula / unformatted) |
| `gsheets_write` | Записать прямоугольник значений с указанной ячейки (RAW или user_input/formulas) |
| `gsheets_append` | Добавить строки в конец листа |
| `gsheets_create` | Создать новую таблицу (опционально с листом, заголовками и данными) |
| `gsheets_clear` | Очистить содержимое листа/диапазона (значения) |
| `gsheets_sheet` | Управление вкладками: add / rename / delete / resize / duplicate / list |
| `gsheets_format` | Форматирование: жирная шапка, заливка/цвет, авто-фильтр, закрепление rows/cols, ширины/высоты |
| `gsheets_batch` | Пакетное чтение (get) или запись (put) нескольких диапазонов одним запросом |
| `gsheets_diff` | Сравнить «до» и «после» значения листа и вернуть изменённые ячейки (старое → новое) |

## Установка в DSH (профиль `web`)

> У пользователя один DSH-профиль — `web` (в `%USERPROFILE%\.dsh\profiles\web`);
> рабочая папка агента — не DSH-профиль, туда плагины не ставятся.

Изменения в двух файлах профиля (можно без `pnpm add` — прямая правка):

**1. `package.json`** — добавить file:-зависимость в блок `dependencies`
(укажите фактический путь к папке плагина):

```json
"utm-gsheets": "file:<абсолютный-путь-к-плагину>/gsheets"
```

**2. `cordis.patch.yml` — только через `insert:`** (голая строка `- id:`
молча патчит существующую запись и пропускается для новых плагинов):

```yaml
- insert:
    - id: utm-gsheets
      name: utm-gsheets
      config:
        token_path: "<путь-к-google_token.json>"
```

3. Патч подхватывается горячо (Cordis HMR), но **новый пакет в `node_modules`
   подхватится только после перезапуска `dsh web`** — перезапустите и
   обновите страницу GUI. Тулы появятся как `gsheets_*`.

> **Путь к токену** можно также задать переменной `GSHEETS_TOKEN_PATH` (или
> `client_id`/`client_secret` через `GSHEETS_CLIENT_ID`/`GSHEETS_CLIENT_SECRET`).
> В конфиге хранится только путь — сам файл токена в репозиторий никогда не
> попадает, и данных о конкретной машине/логинах в исходниках нет.

## Безопасность

- Токен `google_token.json` **никогда не попадает в репозиторий** — в
  `cordis.patch.yml` только его путь.
- Авторизация — OAuth2 refresh (`grant_type=refresh_token`), access-токен
  обновляется автоматически при истечении или 401.

## Тесты

```powershell
cd <plugins-dir>
node test/run-tests.mjs      # чистые утилиты + request-билдеры + каталог тулов (без сети)
node test/live-smoke.mjs     # живой smoke против реального Google аккаунта (создаёт/чистит таблицу)
```

> Live-проверка требует реального токена и **не входит в авто-тесты**. Она
> создаёт одноразовую таблицу, прогоняет get/format/batch/sheet/diff/write и
> удаляет её через Drive API — мусора в аккаунте не остаётся.
